## Задача

Выбрать, когда запускать следующую команду и должна ли она менять состояние текущей оболочки.

## Последовательности

```bash
false; printf 'after semicolon\n'
false && printf 'not printed\n'
false || printf 'fallback\n'
true && printf 'success\n'
```

Ожидаются `after semicolon`, `fallback`, `success`.

| Синтаксис | Когда выполняется правая команда |
|---|---|
| `a; b` | После завершения `a`, независимо от её статуса |
| `a && b` | Если `a` завершилась с кодом 0 |
| `a \|\| b` | Если `a` завершилась с ненулевым кодом |

Перевод строки обычно разделяет команды так же, как `;`. Запись `a && b || c` — цепочка проверок статуса, а не полная замена `if`: `c` выполнится и при ошибке `b`.

## Группа в текущей оболочке

```bash
value=before
{ value=after; printf '%s\n' "$value"; }
printf '%s\n' "$value"
```

Обе строки содержат `after`: группа `{ ...; }` исполняется в текущей оболочке, если не помещена в контекст отдельного процесса. После `{` нужен пробел, перед `}` — `;` или перевод строки.

## Подоболочка

```bash
value=before
( value=inside; printf '%s\n' "$value" )
printf '%s\n' "$value"
```

Получится `inside`, затем `before`: `( ... )` выполняет команды в отдельной среде. Изменения переменных и `cd` оттуда не меняют родительскую оболочку.

## Группа справа от pipe

```bash
printf 'first\nsecond\n' | {
    read -r first_line
    printf 'header=%s\n' "$first_line"
    cat
}
```

Получится `header=first`, затем `second`. `read` потребляет одну строку, `cat` — остаток того же потока. В обычной конфигурации Bash части pipeline выполняются в подоболочках, поэтому переменная `first_line` справа от pipe не сохраняется в родительской оболочке. Этот приём используется в консоли кросс-отладки.

## Проверка

Почему группа справа от `|` не читает первую строку дважды? `read` уже забрал её из потока; `cat` продолжает с оставшихся данных.
