## Задача

Запустить процесс в фоне, дождаться его завершения и понять, как терминал связывается с SSH и приложением.

## Фоновый процесс

```bash
sleep 30 &
pid=$!
printf 'pid=%s\n' "$pid"
kill "$pid"
wait "$pid"
printf 'status=%s\n' "$?"
```

`&` запускает команду в фоне. `$!` содержит PID последнего фонового процесса. `kill` без указания сигнала посылает SIGTERM — просьбу завершиться; процесс может обработать её. `wait` ожидает завершения и возвращает его статус. Обычно после SIGTERM он равен 143; сигнал мог прийти до фактического запуска `sleep`, поэтому не полагайтесь на точный вывод диагностического сообщения.

Ctrl+C в терминале обычно посылает SIGINT его активной группе процессов. Ctrl+D — не сигнал: при обычном построчном вводе на пустой строке он сообщает об окончании ввода. Команда `kill -9` применяет SIGKILL: его нельзя обработать; для обычного завершения примера он не нужен.

## exec

```bash
bash -c 'printf "before\n"; exec printf "replacement\n"; printf "not printed\n"'
```

Появятся `before` и `replacement`. `exec` заменяет текущую оболочку другой программой, поэтому третья команда не выполняется. В наших скриптах это помогает связать жизнь скрипта с запущенным SSH или приложением.

## Уборка при завершении

```bash
mkdir -p "$HOME/work/console-lab/processes"
cd "$HOME/work/console-lab/processes"
cat > cleanup.sh <<'EOF'
#!/usr/bin/env bash
file=$(mktemp)
trap 'rm -f "$file"' EXIT
printf 'temporary data\n' > "$file"
cat "$file"
EOF
bash cleanup.sh
```

Скрипт печатает `temporary data` и при обычном завершении удаляет созданный временный файл. `trap` сохраняет команду для последующего выполнения. Одинарные кавычки откладывают раскрытие `$file`. `EXIT` не обеспечивает уборку при SIGKILL или аварийном выключении системы.

## Терминал и SSH

В интерактивном терминале выполните `tty`: ожидается путь вида `/dev/pts/N`. В процессе без терминала команда может сообщить `not a tty`. TTY — интерфейс терминала, PTY — его программная реализация; путь обозначает устройство в той системе, где команда выполнена.

| Команда | Что означает |
|---|---|
| `ssh pi-dev` | Интерактивное подключение к устройству по ранее настроенному алиасу |
| `ssh pi-dev pwd` | Выполнение команды на устройстве |
| `ssh -t pi-dev 'tty; sleep 5'` | Запрос удалённого терминала и удержание соединения пять секунд |
| `ssh -T pi-dev pwd` | Выполнение без выделения терминала |

Для этих SSH-примеров отдельно нужен [настроенный доступ](../ssh/README.md). Они необязательны для локальной части урока. Два `-t` (`-tt`) принудительно запрашивают терминал, даже если stdin SSH сам не терминал.

## Разбор консоли кросс-отладки

Откройте [debug-console.sh](../cross/example/scripts/debug-console.sh). Теперь знакомы все его конструкции: переменная пути, `trap`, `exec`, pipe, группа команд, `read`, удаление суффикса и `cat`.

Первую строку SSH с адресом TTY скрипт сохраняет локально; остальной вывод показывает пользователю. Клавиатурный ввод передаётся SSH напрямую. Второй скрипт подключает stdin/stdout/stderr приложения к этому TTY. На target работает приложение, на host — GDB; протокол GDB и консоль приложения используют разные SSH-соединения.
