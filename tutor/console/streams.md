## Задача

Отделить данные программы от ошибок, записать вывод в файл и соединить две команды. Нужна только оболочка Bash.

## Три потока

| Номер | Имя | Назначение |
|---|---|---|
| 0 | stdin | Входные данные |
| 1 | stdout | Обычный вывод |
| 2 | stderr | Сообщения об ошибках |

По умолчанию в интерактивном терминале ввод идёт с клавиатуры, а оба потока вывода видны в одном окне. Номер потока — файловый дескриптор процесса.

## Практика

```bash
mkdir -p "$HOME/work/console-lab/streams"
cd "$HOME/work/console-lab/streams"
printf 'first\n' > output.txt
printf 'second\n' >> output.txt
cat < output.txt
```

`>` создаёт или перезаписывает файл. `>>` дописывает в конец. `<` открывает файл как stdin команды. Ожидаются строки `first` и `second`. В этом примере `cat` не получает имя файла аргументом — данные приходят через stdin.

## Обычный вывод и ошибки

```bash
bash -c 'printf "data\n"; printf "error\n" >&2' > data.txt 2> errors.txt
cat data.txt
cat errors.txt
```

`bash -c` выполняет строку как код Bash. Внутри неё `>&2` направляет вывод второго `printf` в stderr. Снаружи `> data.txt` перенаправляет stdout, а `2> errors.txt` — stderr. Ожидаются `data` и `error` в разных файлах.

Для общего файла:

```bash
bash -c 'printf "data\n"; printf "error\n" >&2' > all.txt 2>&1
cat all.txt
```

`2>&1` направляет stderr туда, куда **в этот момент** направлен stdout. Перенаправления применяются слева направо: `> all.txt 2>&1` и `2>&1 > all.txt` не равнозначны.

## Pipe

```bash
printf 'one\ntwo\n' | wc -l
printf 'visible\n' | tee saved.txt
cat saved.txt
```

`|` соединяет stdout первой команды со stdin второй. `wc -l` посчитает две строки. `tee` одновременно покажет `visible` и запишет её в файл. Stderr не входит в pipe автоматически.

Без `pipefail` результат pipe определяется последней командой:

```bash
false | cat
printf 'status=%s\n' "$?"
```

Получится `status=0`: `cat` успешно прочитал пустой поток. Это не означает, что первая команда была успешна.

## Проверка

Объясните разницу между `cat file.txt` и `cat < file.txt`: в первом случае программа сама открывает файл, во втором его открывает оболочка и подаёт содержимое на stdin.
