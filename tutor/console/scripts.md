## Задача

Создать небольшой скрипт и запустить его с аргументом. Все файлы создаём в учебной папке.

## Готовый скрипт

```bash
mkdir -p "$HOME/work/console-lab/scripts"
cd "$HOME/work/console-lab/scripts"
cat > hello.sh <<'EOF'
#!/usr/bin/env bash
name=$1
printf 'Hello, %s\n' "$name"
EOF
bash hello.sh Linux
chmod u+x hello.sh
./hello.sh Linux
```

Оба запуска печатают `Hello, Linux`. `<<'EOF'` передаёт следующие строки на stdin `cat` до строки `EOF`; кавычки запрещают раскрывать `$1` при создании файла. В результате подстановка выполняется позже, при запуске скрипта.

`#!/usr/bin/env bash` выбирает интерпретатор при прямом запуске `./hello.sh`. Для `bash hello.sh` он уже выбран явно. `./` означает файл из текущей папки; иначе оболочка искала бы команду по `PATH`. `$1` — первый аргумент, `$2` — второй, `$@` — все аргументы; `"$@"` сохраняет каждый отдельным аргументом.

## Условие

```bash
name=Linux
if [ "$name" = Linux ]; then
    printf 'known name\n'
else
    printf 'other name\n'
fi
```

`[` — команда проверки, поэтому пробелы вокруг её аргументов обязательны; `]` — её последний аргумент. `if` проверяет код завершения команды: 0 выбирает ветку `then`. Здесь ожидается `known name`. Конструкция `[[ ... ]]` относится к Bash и не равнозначна переносимой команде `[` во всех деталях.

## Цикл и чтение строки

```bash
for item in one two; do
    printf '%s\n' "$item"
done
printf 'first\nsecond\n' | while IFS= read -r line; do
    printf 'line=%s\n' "$line"
done
```

`for` проходит по указанным словам. `while` повторяет тело, пока команда проверки успешна. `read` возвращает неуспех при окончании потока; `IFS=` не обрезает пробелы по краям строки, `-r` сохраняет обратные слеши. Этот пример читает строки, заканчивающиеся переводом строки.

## Ошибки и set -e

```bash
cat > stop-on-error.sh <<'EOF'
#!/usr/bin/env bash
set -e
false
printf 'not printed\n'
EOF
bash stop-on-error.sh
printf 'status=%s\n' "$?"
```

Последняя строка показывает `status=1`, а `not printed` не появляется. `set -e` завершил **дочерний скрипт**, но не интерактивную оболочку, из которой он запущен. Это не универсальная обработка ошибок: в условиях `if`, проверяемых частях `&&`/`||` и pipeline действуют исключения. В коротком скрипте с одной командой его код завершения и так равен коду этой команды.
