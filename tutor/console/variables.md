## Задача

Понять, что оболочка подставляет до запуска программы и какие значения передаются дочерним процессам.

## Переменная и кавычки

```bash
name='Linux console'
printf '%s\n' "$name"
printf '%s\n' '$name'
```

Получится `Linux console`, затем буквально `$name`. `name=...` задаёт переменную; пробелов вокруг `=` нет. Одинарные кавычки сохраняют текст буквально. Двойные позволяют раскрывать переменные и сохраняют результат одним аргументом.

Не путайте `$name` — значение переменной — и имя `name` без `$`, используемое при присваивании. Обычно пишите `"$name"`, когда передаёте значение аргументом: без кавычек пробелы и шаблоны файлов могут изменить число аргументов.

## Окружение

```bash
export CONSOLE_GREETING='hello'
bash -c 'printf "%s\n" "$CONSOLE_GREETING"'
```

`export` передаёт значение новым дочерним процессам. Уже работающий процесс его не получает. Дочерний процесс не может таким присваиванием изменить окружение родителя.

Пути можно формировать из предыдущих переменных:

```bash
work_dir="$HOME/work/console-lab"
build_dir="$work_dir/build"
app_path="$build_dir/hello"
printf '%s\n' "$app_path"
```

Подстановка происходит при выполнении каждой строки. Если потом изменить `work_dir`, уже записанные `build_dir` и `app_path` сами не пересчитаются.

## Результат команды

```bash
current_dir=$(pwd)
printf '%s\n' "$current_dir"
```

`$(...)` запускает команду и подставляет её stdout; завершающие переводы строк удаляются. Это не то же самое, что `( ... )` без `$`, создающее подоболочку.

## Удаление суффикса и специальный символ

```bash
filename=example.txt
printf '%s\n' "${filename%.txt}"
target_tty=$'/dev/pts/2\r'
printf '%s\n' "${target_tty%$'\r'}"
```

Получится `example`, затем `/dev/pts/2`. `${var%suffix}` удаляет совпавший суффикс; если его нет, значение не меняется. `$'\r'` задаёт carriage return. ANSI-C quoting `$'...'` здесь рассматриваем как возможность Bash; не рассчитывайте на её поддержку в `dash`, который часто используется как `sh` в Ubuntu/Debian.

## Проверка

Чем `"$HOME/work"` отличается от `'~/work'`? Первая строка содержит раскрытый домашний каталог; вторая — буквальный текст с `~`.
