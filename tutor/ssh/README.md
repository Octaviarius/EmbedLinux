## Цель и окружение

Настроим вход на целевое устройство по IP или имени хоста, затем по SSH-ключу и короткому алиасу `pi-dev`. Это первый шаг перед [нативной разработкой](../native/README.md) и кросс-разработкой.

Компьютер — Ubuntu в WSL либо обычная Ubuntu/Debian; подготовка описана в [рабочем окружении](../../environment/README.md). Пример устройства — [Raspberry Pi Zero 2 W (`rpi0-2w`)](../../hardware/rpi0-2w/README.md) с Raspberry Pi OS. Для нашего учебного устройства пользователь — `dev`, пароль — `1`. Это заданные нами учётные данные, не стандартный пароль Raspberry Pi OS. Адрес `192.168.1.50` замените адресом своего устройства.

Команды подключения и настройки клиента выполняются **в Bash на компьютере, в WSL**. Команды сервера явно отмечены как выполняемые на устройстве. Windows и WSL по умолчанию используют разные SSH-конфигурации: для задач VS Code в WSL доступ проверяйте именно из WSL.

## Включите SSH на устройстве

При записи Raspberry Pi OS через Imager задайте пользователя, сеть и включите SSH в `Customisation → Remote Access`. Для первого входа и установки ключа можно выбрать аутентификацию по паролю. Если выбираете только ключ, сразу укажите публичный ключ компьютера: установка через `ssh-copy-id` с паролем тогда не подойдёт.

В уже работающей Raspberry Pi OS SSH можно включить через `sudo raspi-config`. Альтернатива для системы с установленным OpenSSH и systemd — выполнить **на устройстве** из локального терминала или UART:

```bash
sudo systemctl enable --now ssh
systemctl is-active ssh
```

Ожидается `active`. Подробнее: [официальная инструкция Raspberry Pi](https://www.raspberrypi.com/documentation/computers/remote-access.html).

Для резервного входа на `rpi0-2w` настройте [UART-консоль](../../hardware/rpi0-2w/README.md#отладочная-консоль-через-uart). Если плата не подключается к Wi-Fi WPA2/WPA3, посмотрите [кейс SAE](../../hardware/rpi0-2w/wifi-wpa3-sae.md): сначала нужен работающий сетевой доступ.

## Подключитесь по IP или имени хоста

IP устройства можно узнать в списке клиентов роутера или командой `hostname -I` **на устройстве**. При нескольких адресах выберите доступный с компьютера адрес Wi-Fi или Ethernet.

Первое подключение **из WSL**:

```bash
ssh dev@192.168.1.50
```

При первом соединении SSH попросит подтвердить ключ сервера, затем запросит пароль пользователя устройства. После входа выполните `hostname`, чтобы проверить устройство; `exit` возвращает в терминал WSL.

Если имя платы — `raspberrypi`, можно использовать:

```bash
ssh dev@raspberrypi.local
```

Для `.local` нужен mDNS: плата отвечает на запрос своего имени, а компьютер должен уметь отправить запрос и получить ответ. Настройка обеих сторон описана ниже. Имя без `.local`, например `raspberrypi`, работает только при соответствующем разрешении через DNS или файл `hosts`. При DHCP адрес может меняться; при необходимости закрепите его на роутере.

## Где работает mDNS и как его включить

mDNS ищет устройство по имени в локальной сети без отдельного DNS-сервера. Для `ssh dev@raspberrypi.local` нужны три условия:

- **На плате** работает служба, публикующая её имя — в Raspberry Pi OS это Avahi.
- **В Ubuntu/WSL компьютера** настроено разрешение имён `.local`.
- **Между ними** проходит multicast-трафик mDNS (UDP 5353). Гостевая сеть, изоляция клиентов или виртуальная сеть WSL могут этому мешать.

### На Raspberry Pi

Подключитесь по IP или UART. Команды выполняются **на плате**:

```bash
hostname
systemctl is-active avahi-daemon
```

Для имени `raspberrypi.local` первая команда должна показать `raspberrypi`, вторая — `active`. Если имя другое, используйте `<это-имя>.local`.

Если Avahi не установлен или выключен:

```bash
sudo apt update
sudo apt install avahi-daemon
sudo systemctl enable --now avahi-daemon
```

В обычной Raspberry Pi OS поддержка уже предусмотрена. См. [удалённый доступ Raspberry Pi](https://www.raspberrypi.com/documentation/computers/remote-access.html) и [описание Avahi](https://manpages.debian.org/trixie/avahi-daemon/avahi-daemon.8.en.html).

### На компьютере в Ubuntu/Debian или WSL

Команды выполняются **в Linux-терминале компьютера**, не на плате:

```bash
getent hosts raspberrypi.local
```

Если получен IP платы, разрешение имени уже работает. Если нет, для варианта с Avahi установите:

```bash
sudo apt update
sudo apt install avahi-daemon avahi-utils libnss-mdns
sudo systemctl enable --now avahi-daemon
avahi-resolve-host-name -4 raspberrypi.local
getent hosts raspberrypi.local
```

Avahi выполняет mDNS-запросы, а `libnss-mdns` подключает их к системному поиску имён, которым пользуется SSH. Если `avahi-resolve-host-name` находит плату, а `getent` — нет, проверьте **`/etc/nsswitch.conf` на компьютере**: в строке `hosts:` должен быть `mdns4_minimal` перед `dns`. Пример этой строки:

```text
hosts: files mdns4_minimal [NOTFOUND=return] dns
```

Остальные строки файла и дополнительные модули вашей конфигурации сохраняйте. Обычно пакет добавляет настройку сам. См. [инструкцию пакета libnss-mdns](https://sources.debian.org/src/nss-mdns/0.15.1-5/debian/README.Debian).

Эти команды `systemctl` предполагают работающий systemd. Если в WSL он не включён, настройте его по [инструкции Microsoft](https://learn.microsoft.com/en-us/windows/wsl/systemd) либо пока подключайтесь по IP.

### Особенность сети WSL 2

Настройка Avahi не исправляет отсутствие multicast-связи с платой. В WSL 2 с обычной NAT-сетью mDNS из локальной сети может быть недоступен, даже когда `.local` работает в Windows.

На Windows 11 22H2 и новее WSL поддерживает режим `mirrored` с multicast. Если хотите использовать его, добавьте или измените параметр в **`%USERPROFILE%\.wslconfig` в Windows**:

```ini
[wsl2]
networkingMode=mirrored
```

Сохраните остальные настройки файла. Завершите работу в WSL, затем выполните **в PowerShell**:

```powershell
wsl --shutdown
```

Заново откройте Ubuntu/WSL и повторите `getent hosts raspberrypi.local`, затем `ssh dev@raspberrypi.local`. Режим `mirrored` поддерживает multicast, но доступ также зависит от firewall и локальной сети. См. [сетевые режимы WSL](https://learn.microsoft.com/en-us/windows/wsl/networking).

Если имя по-прежнему не находится, используйте IP в SSH и в `HostName`: для дальнейших туториалов mDNS не обязателен.

## Настройте вход по ключу

На компьютере **в WSL** создайте ключ, если ещё нет подходящего:

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
ssh-keygen -t ed25519 -f ~/.ssh/rpi-dev
ssh-copy-id -i ~/.ssh/rpi-dev.pub dev@192.168.1.50
```

Не перезаписывайте существующий ключ. Если у ключа есть парольная фраза, загрузите его в агент текущего сеанса WSL:

```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/rpi-dev
```

## Задайте алиас подключения

Если mDNS не работает, а IP меняется, оставьте постоянный алиас **`pi-dev`** и обновляйте только `HostName` через скрипт ниже. Новый IP узнайте на плате через `hostname -I` или в списке клиентов роутера. Повторно устанавливать SSH-ключ не нужно.

Для дальнейших задач VS Code удобнее вариант с `Include`: обычные `ssh pi-dev`, scp и rsync будут использовать актуальный адрес. Отдельный конфиг через `-F` подходит, если не хотите менять общий конфиг.

### Вариант с Include

В **`~/.ssh/config` внутри WSL** разместите `Include` в начале файла, вне блоков `Host` и `Match`. Для нового файла полное содержимое ([готовый файл](ssh-main-config)):

```sshconfig
Include ~/.ssh/conf.d/*
```

Существующие настройки сохраните ниже. В SSH обычно применяется первое найденное значение параметра. См. [Include в OpenSSH](https://man.openbsd.org/ssh_config).

Файл **`~/.ssh/conf.d/pi-dev`** ([пример](pi-dev)):

```sshconfig
Host pi-dev
    HostName 192.168.9.92
    User dev
    IdentityFile ~/.ssh/rpi-dev
    IdentitiesOnly yes
    HostKeyAlias rpi0-2w
```

`pi-dev` — алиас подключения; `HostKeyAlias rpi0-2w` — постоянное имя для проверки ключа сервера в known_hosts при смене IP. Это не отключает проверку ключа. При первом использовании этого имени подтвердите ключ именно вашей платы.

Из корня EmbedLinux **в Bash WSL**, передайте текущий IP генератору:

```bash
bash tutor/ssh/generate-ssh-config.sh 192.168.9.92
chmod 600 ~/.ssh/config
ssh pi-dev
```

Когда IP изменится, повторите только запуск скрипта с новым адресом. Скрипт перезаписывает один файл `pi-dev`, общий конфиг и ключ не меняет.

### Вариант с отдельным конфигом через -F

Сгенерируйте тот же конфиг в отдельный файл. Второй аргумент скрипта — путь назначения:

```bash
bash tutor/ssh/generate-ssh-config.sh 192.168.9.92 "$HOME/.ssh/pi-dev"
ssh -F "$HOME/.ssh/pi-dev" pi-dev
```

Общий `~/.ssh/config` для этого варианта менять не нужно. `-F` выбирает отдельный конфиг вместо обычного пользовательского; задавайте его при каждом подключении. При смене IP повторите генерацию с тем же путём файла.

Для готовых задач нативного туториала используйте вариант `Include`. Если выбираете `-F`, этот аргумент потребуется добавить в SSH-команды задач, SSH-транспорт rsync и `pipeArgs` отладчика. См. [параметры ssh](https://man.openbsd.org/ssh).

### Готовый Bash-скрипт

[generate-ssh-config.sh](generate-ssh-config.sh) создаёт конфиг для пользователя `dev`, ключа `~/.ssh/rpi-dev` и алиаса `pi-dev`. Первый аргумент — новый IP, второй необязательный — путь конфига. Пароль в файл не записывается.

```bash
#!/usr/bin/env bash
config_path=${2:-"$HOME/.ssh/conf.d/pi-dev"}
mkdir -p "$(dirname "$config_path")"
umask 077
cat > "$config_path" <<EOF
Host pi-dev
    HostName $1
    User dev
    IdentityFile ~/.ssh/rpi-dev
    IdentitiesOnly yes
    HostKeyAlias rpi0-2w
EOF
chmod 600 "$config_path"
```

## Проверьте доступ для задач VS Code

Из того же WSL-терминала, из которого будете запускать VS Code:

```bash
ssh -o BatchMode=yes pi-dev 'whoami; hostname'
```

Для варианта `-F` добавьте `-F "$HOME/.ssh/pi-dev"` в проверочную команду. Ожидаются пользователь и имя устройства без запроса ввода. `BatchMode=yes` запрещает интерактивные запросы: такая проверка подходит для автоматических задач сборки. Если ключ защищён парольной фразой, он должен быть загружен в агент, доступный процессу VS Code. Запускайте `code .` из терминала, где работает агент; уже открытое окно может не получить его окружение.

После этого в [нативном туториале](../native/README.md) задайте `target.host` равным `pi-dev`.

| Ошибка | Что проверить |
|---|---|
| Имя хоста не найдено | Подключение по IP и разрешение имени именно в WSL |
| `Connection refused` | SSH-сервер устройства и правильность адреса |
| Тайм-аут | Подключение устройства к сети и доступность маршрута с компьютера |
| `Permission denied` | Пользователя устройства, установленный публичный ключ и агент |
| Интерактивный вход работает, BatchMode — нет | Ключ, агент и отсутствие зависимости от ввода пароля |

Для диагностики алиаса выполните `ssh -G pi-dev`: параметр `hostname` должен показывать IP устройства. Если там осталось `pi-dev`, проверьте путь в `Include` и расположение файла. В нашем случае `Include` указывал на `conf.d/*`, а файл лежал в `conf.d/pi-dev`.
