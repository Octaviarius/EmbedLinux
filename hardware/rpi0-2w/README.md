# Raspberry Pi Zero 2 W

**Мнемоника в проекте:** `rpi0-2w`.

Компактный одноплатный компьютер для приложений под Linux. В туториалах его можно использовать для изучения загрузки системы, разработки приложений, сетевого обмена и работы с периферией.

## Основные характеристики

| Параметр | Значение |
|---|---|
| SiP / процессор | Raspberry Pi RP3A0 с Broadcom BCM2710A1 |
| CPU | 4 ядра Arm Cortex-A53, 1 ГГц, поддержка AArch64 |
| Оперативная память | 512 МБ LPDDR2 |
| Накопитель | Карта microSD |
| Wi-Fi | 2,4 ГГц, IEEE 802.11 b/g/n |
| Bluetooth | 4.2, BLE |
| USB | Один интерфейс USB 2.0 OTG, разъём micro USB |
| Видеовыход | Mini HDMI |
| Камера | Разъём CSI-2 |
| GPIO | Площадка 40-контактного разъёма, совместимого с HAT; у Zero 2 W штыри штатно не установлены |
| Питание | 5 В через отдельный micro USB; в спецификации указан источник 5 В / 2,5 А |
| Размеры | 65 × 30 мм |

Характеристики приведены по [официальному Product brief](https://datasheets.raspberrypi.com/rpizero2/raspberry-pi-zero-2-w-product-brief.pdf).

## Подключение и периферия

- **Сеть:** встроенный Wi-Fi работает в диапазоне 2,4 ГГц. Для подключения по кабелю понадобится дополнительный сетевой адаптер; встроенного Ethernet-разъёма нет.
- **USB:** разъём данных поддерживает OTG. Отдельный разъём питания не заменяет USB-порт данных; для подключения USB-периферии подберите подходящий OTG-переходник.
- **GPIO:** линии могут использоваться для цифрового ввода и вывода, UART, I²C и SPI. Назначение контактов и включение интерфейсов зависят от выбранной конфигурации.
- **Уровни сигналов:** GPIO работают с логикой 3,3 В. Подача 5 В непосредственно на сигнальный GPIO недопустима; для устройств с другими уровнями используйте согласование.
- **Разъём:** для подключения проводами к обычной Zero 2 W потребуется установить гребёнку либо использовать подходящее соединение с площадками платы.

Расположение контактов и электрические параметры описаны в [официальном разделе GPIO](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html#gpio). При подключении различайте физические номера контактов разъёма и номера GPIO.

## Отладочная консоль через UART

UART-консоль даёт доступ к терминалу Linux без Wi-Fi и SSH. Её стоит настроить и проверить заранее: при недоступности сети можно войти на устройство, посмотреть журналы и исправить настройки. Это последовательная консоль ОС, а не аппаратный интерфейс отладки процессора; возможность входа зависит от загрузки системы и работы службы входа.

### Что понадобится

- USB–UART адаптер с **логическими уровнями TX/RX 3,3 В**. Уточните именно уровни сигналов: переключатель питания адаптера не всегда переключает уровни UART.
- Три провода для GND, TX и RX.
- Установленная гребёнка или другое надёжное соединение с площадками 40-контактного разъёма.
- Обычное питание Raspberry Pi через её разъём питания micro USB.
- Любое приложение компьютера для работы с последовательным портом.

Нужен UART с логикой 3,3 В, **не RS-232**. Сигнальные GPIO платы не допускают 5 В. Питание VCC адаптера к плате в описанном подключении не подключается. См. [электрические параметры GPIO](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html#voltage-specifications).

### Подключение к пинам

Перед соединением отключите питание платы и USB адаптера. В таблице указаны **физические номера контактов** разъёма:

| Контакт Raspberry Pi | Назначение на плате | Контакт USB–UART адаптера |
|---|---|---|
| **6** | GND | GND |
| **8**, GPIO14 | TXD — передача платы | RXD — приём адаптера |
| **10**, GPIO15 | RXD — приём платы | TXD — передача адаптера |

TX и RX соединяются перекрёстно, GND — с GND. Контакты питания адаптера, RTS и CTS оставьте неподключёнными.

Не определяйте номера по положению платы на столе: найдите контакт 1 по маркировке и сверьтесь с [официальной распиновкой](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html#gpio). Назначение UART на GPIO14/15 подтверждено в [документации UART](https://www.raspberrypi.com/documentation/computers/configuration.html#uarts).

### Включение консоли при записи образа через Imager

В Raspberry Pi Imager есть настройка последовательного интерфейса; она подтверждена для [выпуска 2.0.12](https://github.com/raspberrypi/rpi-imager/releases/tag/v2.0.12). Пункт отображается, если выбранные плата и образ ОС поддерживают эту настройку.

При подготовке новой microSD **на компьютере**:

1. Выберите Raspberry Pi Zero 2 W, подходящий образ Raspberry Pi OS и карту для записи.
2. В настройках образа задайте пользователя и пароль: они понадобятся для входа через UART.
3. Откройте `Customisation → Interfaces & Features`.
4. В поле `Enable Serial` выберите **`Console & Hardware`** — консоль входа вместе с аппаратным UART.
5. Завершите настройку и запись образа. Подключите адаптер по таблице выше и проверьте вход через UART после первого запуска платы.

Режим `Hardware` предназначен для UART без консоли входа и для резервного терминального доступа не подходит. `Default` оставляет выбор системе, поэтому для этого сценария явно выбирайте `Console & Hardware`. Названия и доступность пунктов проверены по [официальному коду интерфейса Imager 2.0.12](https://github.com/raspberrypi/rpi-imager/blob/v2.0.12/src/wizard/IfAndFeaturesCustomizationStep.qml).

Если такого раздела или поля нет, используйте настройку в работающей системе ниже либо отредактируйте загрузочные файлы microSD после записи образа, **до первого включения**. Отсутствие пункта в Imager не означает, что сама плата не поддерживает UART. Фактическое включение и вход необходимо проверить на выбранном образе; запись карты через Imager в рамках подготовки этого описания не выполнялась.

### Включение консоли в работающей системе

Пока доступ по SSH или локальному терминалу работает, выполните **на Raspberry Pi**:

```bash
sudo raspi-config
```

В разделе `Interface Options` выберите настройку последовательного порта (`Serial Port`; название может отличаться между версиями). Включите **оба** параметра:

- Доступ к оболочке входа через последовательный порт — **Yes**.
- Аппаратный последовательный порт — **Yes**.

Если параметры представлены отдельными пунктами, включите и `Serial Console`, и `Serial Port`. Для аварийного входа недостаточно только включить UART. См. [настройки Raspberry Pi OS](https://www.raspberrypi.com/documentation/computers/configuration.html#serial-port).

Для входа через консоль нужен существующий пользователь с паролем. Если вы пользуетесь только SSH-ключом, задайте пароль своей учётной записи на плате:

```bash
passwd
```

Завершите настройку и перезагрузите плату:

```bash
sudo reboot
```

После перезагрузки проверьте на плате:

```bash
ls -l /dev/serial0
cat /proc/cmdline
```

Должен существовать `/dev/serial0`, а в параметрах ядра — последовательная консоль на скорости 115200. В зависимости от настройки там может быть `console=serial0,115200` либо имя реального UART.

У Zero 2 W штатный UART консоли — mini UART, а PL011 используется Bluetooth. `enable_uart=1` включает основной UART и фиксирует частоту ядра VPU для работы mini UART. Поэтому в инструкциях используем алиас `/dev/serial0`, а не жёстко заданное `/dev/ttyAMA0`. Отключать Bluetooth для описанного подключения не требуется. См. [назначение UART и частоту mini UART](https://www.raspberrypi.com/documentation/computers/configuration.html#uarts).

### Настройка microSD без сетевого доступа

Если сеть уже недоступна и консоль не настроена, выключите плату и подключите microSD к компьютеру через кардридер. Откройте загрузочный FAT-раздел карты. В его корне находятся `config.txt` и `cmdline.txt`; в работающей современной Raspberry Pi OS они доступны как `/boot/firmware/config.txt` и `/boot/firmware/cmdline.txt` (в старых образах — `/boot/`).

Сначала сохраните копии этих файлов. **Редактируйте существующие файлы, не заменяйте их целиком примером**: они содержат настройки загрузки именно вашей системы.

В `config.txt` обеспечьте включение UART. Если параметр уже есть в применяемой секции, исправьте его значение. Если его нет, добавьте в конец файла:

```ini
[all]
enable_uart=1
```

В `cmdline.txt` добавьте через пробел параметр:

```text
console=serial0,115200
```

**Весь `cmdline.txt` должен оставаться одной строкой.** Сохраните остальные параметры, особенно `root=...`, `rootfstype=...` и `rootwait`; не добавляйте вторую строку и не дублируйте уже имеющуюся настройку последовательной консоли. Для более подробного вывода при загрузке можно убрать отдельный параметр `quiet`, если он присутствует.

Верните карту в плату и включите её с подключённым UART. Параметр `console` направляет сообщения ядра в UART; в обычной Raspberry Pi OS на systemd для последовательной консоли также запускается служба входа через [systemd-getty-generator](https://manpages.debian.org/trixie/systemd/systemd-getty-generator.8.en.html). Изменённый образ с отключённой службой входа может потребовать отдельной настройки. Пользователь и его пароль должны уже существовать — UART не обходит авторизацию.

### Подключение с компьютера

Подключите USB–UART к компьютеру и определите назначенный ему порт: например, `COM4` в Windows или `/dev/ttyUSB0` / `/dev/ttyACM0` в Linux. Номер и имя зависят от адаптера и системы; при необходимости установите драйвер производителя адаптера.

В любом приложении для последовательного порта задайте:

| Параметр | Значение |
|---|---|
| Порт | Порт подключённого USB–UART адаптера |
| Скорость | **115200 бит/с** |
| Биты данных | **8** |
| Чётность | **Нет (None)** |
| Стоповые биты | **1** |
| Управление потоком | **Нет (None)**, без RTS/CTS и XON/XOFF |

Это режим **115200, 8N1**. Откройте соединение до подачи питания на плату, чтобы увидеть доступные сообщения загрузки. После загрузки нажмите Enter, дождитесь приглашения входа и введите пользователя и пароль; символы пароля не отображаются.

Приложение должно иметь доступ к адаптеру. При работе с VS Code в WSL консоль можно независимо открыть в Windows: USB-порт Windows не становится автоматически устройством `/dev/ttyUSB0` внутри WSL.

### Проверка и диагностика

После входа через UART выполните **на плате**:

```bash
whoami
hostname
ip -br address
journalctl -b -p warning --no-pager
```

Проверьте, что вход и команды работают при недоступном сетевом подключении. После этой проверки UART можно использовать как резервный способ доступа для туториалов.

| Симптом | Что проверить |
|---|---|
| Полностью пустой экран | Порт адаптера, питание платы, GND, соединение TX платы с RX адаптера и включение UART |
| Нечитаемые символы | 115200, 8N1, отсутствие управления потоком; настройки частоты mini UART и `enable_uart=1` |
| Вывод есть, ввод не работает | TX адаптера → RX платы, общий GND и отключённое управление потоком |
| Есть сообщения, но нет приглашения входа | Нажать Enter, дождаться загрузки; проверить включение Serial Console и службы входа |
| Вход отклонён | Пользователя и пароль целевой системы; SSH-ключ здесь не используется |
| Порт не открывается | Драйвер, права доступа и другое приложение, уже занявшее порт |

Пока UART используется консолью, не используйте те же GPIO14/15 для обмена с другим устройством. Физическое подключение и вход на конкретной плате в рамках подготовки описания не проверены.

## Особенности для туториалов

512 МБ памяти нужно учитывать при выборе программного окружения и числа параллельных процессов сборки. Для работы через терминал и SSH можно использовать систему без графического рабочего стола; тяжёлые сборки удобно выполнять на рабочем компьютере.

Поддержка AArch64 процессором не означает, что установленное пользовательское окружение обязательно 64-битное. Архитектура приложений, версия ОС и подходящий toolchain указываются в конкретном туториале.
